# Справочник API — робот `go2_api` и манипулятор

Ты управляешь роботом через один объект `Go2`. Минимальный пример:

```python
from go2_api import Go2

robot = Go2()                 # Go2(enable_ros2=True) включает мост ROS 2 Humble, доступный при оценке

while robot.step():           # Шаг симуляции, False означает конец попытки
    x, y, yaw = robot.pose()  # Положение: x и y в метрах, yaw в радианах
    robot.drive(vx=0.4, vyaw=0.0)   # Идём вперёд со скоростью 0,4 м/с без поворота
```

`robot.step()` = один тик (применяет команду, шагает физику, обновляет сенсоры). Не вызываешь
`step()` — робот стоит, а время идёт.

## Команды движения

| Вызов | Действие |
|---|---|
| `robot.drive(vx, vyaw, vy=0)` | Идти: `vx` вперёд м/с (≤ ±0.8), `vyaw` поворот рад/с (≤ ±1.5), `vy` боком м/с (≤ ±0.4). Значения вне диапазона обрезаются до границ. |
| `robot.stop()` | `drive(0, 0)`. |
| `robot.stand()` | Стоять на месте. |
| `robot.crouch(height=0.18)` | Присесть (ниже посадка корпуса). |
| `robot.step()` | Продвинуть симуляцию на ОДИН тик. Вызывай каждую итерацию цикла. `False` — попытка окончена. |

Робот **реально идёт**: 12 суставов ног под честной физикой ведёт штатная нейросетевая политика управления походкой.
Значит реальная динамика — инерция, задержка команды, проскальзывание. Веди плавно: ~0.4–0.5 м/с
— надёжный крейсер; резкие развороты на полной скорости или удары в стену роняют робота (это
завершает попытку).

## Сенсоры (только чтение, обновляются каждый `step()`)

| Вызов | Возвращает |
|---|---|
| `robot.pose()` | `(x, y, yaw)` — позиция и курс (ground-truth). |
| `robot.position()` | `(x, y, z)`. |
| `robot.imu()` | `(roll, pitch, yaw)` в радианах. |
| **`robot.lidar()`** | **основной скан для стен и навигации** — полное 3D-облако: 360 × число_слоёв дальностей (м). Стены видны на любой высоте и при качке корпуса. Форму см. `lidar_info()`; готовый рецепт ниже. |
| `robot.lidar_layer()` | 360 дальностей (м) из ОДНОГО слоя — опционально. Слой по умолчанию горизонтальный на высоте сенсора → может скользить ПОВЕРХ низких стен. Для надёжного детекта стен бери `lidar()`. |
| `robot.lidar_info()` | `(h_fov, h_res, max_range, layers, v_fov)`. Пеленг горизонтального индекса `i` ≈ `-h_fov/2 + i*h_fov/(h_res-1)`. |
| `robot.image()` | кадр фронтальной камеры (сырой буфер; W/H — из `camera_info()`). |
| `robot.camera_info()` | `(width, height, fov)`. |
| `robot.time()` | текущее время симуляции (с). **По нему судят** — финишируй за минимальное sim-время. |

Ни телепортации, ни доступа к внутренним данным судьи, ни прямого управления моторами ног нет — робот работает как обычный агент, а не привилегированный узел (Supervisor) Webots.

## Навигация

Хардкод «еду по точкам» будет цепляться за стены. У тебя есть **3D-лидар** и камера — используй.

**Важно про лидар.** Это 3D-купол (несколько слоёв × 360). Один горизонтальный слой (`lidar_layer()`)
сидит на высоте сенсора (~0.46 м) и может проходить ПОВЕРХ низких стен — не полагайся на него для
стен. Бери полное 3D-облако `lidar()` и строй карту препятствий из него: по каждому азимуту — ближайший
возврат, чья 3D-точка ВЫШЕ пола. Это разом (а) видит стены на любой высоте, (б) отсекает пол и плоские
напольные чекпоинты (как препятствия они не мешают — но именно они размечают маршрут, см. ниже).
Очень близкие возвраты (~0.2 м) —
это корпус самого робота (широкие нижне-задние лучи), их тоже отбрось.

```python
import math
def obstacle_scan(robot, floor=0.15, min_r=0.30):
    """360 дальностей до ближайшего вертикального препятствия (стены/столбы/рука); inf = чисто."""
    cloud = robot.lidar()
    _, h, mx, layers, v_fov = robot.lidar_info()
    lz = robot.position()[2] + 0.16               # Примерная высота лидара над полом
    out = [float("inf")] * h
    for L in range(layers):
        s = math.sin(v_fov / 2 - L * (v_fov / (layers - 1)))
        for i in range(h):
            r = cloud[L * h + i]
            if r >= mx or r < min_r:              # Нет отражения или луч попал в корпус робота
                continue
            if lz + r * s < floor:                # Пол и напольные маркеры не считаем препятствиями
                continue
            out[i] = min(out[i], r)
    return out
```

Дальше — как обычно:
1. **Реактивно**: по `obstacle_scan` руль в самый открытый сектор, тормози у стен.
2. **Следование за стеной**: держи целевую дистанцию до стены сбоку.
3. **Карта / SLAM**: копи `obstacle_scan` + `pose()` в сетку занятости и планируй путь.

> Чекпоинты — это светящиеся **напольные** маркеры: их видно камерой/глазом, но в лидаре они на уровне
> пола, поэтому как препятствия они не мешают. **Стоят они вдоль оптимального маршрута к финишу** —
> двигаясь от маркера к маркеру, вы идёте по проходимому и кратчайшему пути. Полный обход трассы
> не нужен: ищите следующий маркер сенсорами и держите курс на него.

## Манипулятор (уровни 2 и 3)

На L2/L3 рядом с трассой стоит **стационарная 4-DOF рука** — она **не на роботе**. Управляешь ею
**по радио** через `robot.arm`, и она работает **параллельно** с собакой. На L2 рука раскладывает
3 цветных шара по слотам → открывает потайную дверь; на L3 вставляет ключ-куб в приёмник → опускает
плиту ворот. Обе задачи — **опциональные короткие пути**: уровень проходится и длинным путём.

Каждый вызов `arm` **неблокирующий**: задал цель/действие — и в том же цикле опрашиваешь
состояние (без активного ожидания в цикле, иначе теряешь параллельность). Координаты — в **системе руки**:
начало в центре пьедестала на полу, `x`/`y` горизонтально, `z` вверх; рабочая зона — радиус
~0.3–0.5 м вокруг пьедестала, высоты захвата от уровня объекта до ~0.55 м.

| Вызов | Действие |
|---|---|
| `robot.arm.move(x, y, z)` | Вести схват к точке (захват сверху — схват смотрит вниз). Затем опрашивай `at_target()`. |
| `robot.arm.at_target()` | `True`, когда кончик дошёл до последней цели (±1.5 см) и остановился. |
| `robot.arm.tip()` | `(x, y, z)` текущая позиция схвата (система руки). |
| `robot.arm.grab()` | Включить магнит — цепляет ближайший объект в ~9 см от схвата. |
| `robot.arm.holding()` | `True`, пока объект удерживается. |
| `robot.arm.release()` | Отпустить — объект остаётся там, где оставил. |
| `robot.arm.stow()` | Сложить руку в парковочную позу. |
| `robot.arm.request_image()` → `robot.arm.image()` | RGB с камеры запястья → `(w, h, BGRA-байты)`. |
| `robot.arm.request_depth()` → `robot.arm.depth()` | Глубина с запястья → `(w, h, float32 в метрах)`. |

**Высота отпускания важна.** Схват держит объект на ~7.5 см ниже кончика, а `release()` оставляет его ровно там, где отпустил (объект **не** падает на площадку). Чтобы укладка засчиталась, отпускай с кончиком на высоте **≥ 0.30 м** — тогда центр объекта попадёт в зачётное окно **0.22–0.55 м**. Слишком низкое отпускание (кончик < 0.30 м) не засчитывается.

Цвет шара/слота читается **камерой запястья**: наведи схват над объектом, запроси кадр и сравни
каналы B/G/R центрального пикселя (кадры в BGRA). Веди руку как маленький неблокирующий автомат
(`к hover → к захвату → grab → поднять → к слоту → release`), по одному переходу на `at_target()`,
— тогда собака едет всё это время. Звенья руки не сталкиваются, захват кинематический, поэтому
станция физически стабильна при любой последовательности.

### Пример автомата руки (скелет)

```python
STATE = "hover"
def arm_tick(arm):
    global STATE
    if STATE == "hover":
        arm.move(bx, by, Z_HOVER)          # Координаты объекта определяем по камере или геометрии
        if arm.at_target(): STATE = "down"
    elif STATE == "down":
        arm.move(bx, by, Z_GRAB)
        if arm.at_target(): arm.grab(); STATE = "lift"
    elif STATE == "lift":
        arm.move(bx, by, Z_HOVER)
        if arm.at_target(): STATE = "to_slot"
    elif STATE == "to_slot":
        arm.move(sx, sy, Z_HOVER)          # Зона нужного цвета
        if arm.at_target(): arm.release(); STATE = "done"
```

## Опционально: ROS 2 (Humble) — доступен на судействе

`Go2(enable_ros2=True)` поднимает мост: публикует `/scan` (LaserScan), `/odom` (Odometry),
`/imu` (Imu) и подписывается на `/cmd_vel` (Twist). Ты по-прежнему зовёшь `robot.step()` в цикле;
мост крутится рядом. Манипулятор в ROS-мост не выведен — им управляй через `robot.arm`.

**Судейский образ содержит ROS 2 Humble** (Ubuntu 22.04, Python 3.10), проверено на судейском стенде:

- `rclpy`, `geometry_msgs` / `sensor_msgs` / `nav_msgs`, `tf2_ros`;
- **`navigation2` (Nav2)**, **`slam_toolbox`** — можно строить SLAM/планирование;
- DDS — CycloneDDS, режим `ROS_LOCALHOST_ONLY=1` (мост замкнут на loopback).

> Файловая система Linux регистрозависима: `MyModule.py` и `mymodule` — разные имена; следите за регистром в импортах.

Так что решения на ROS 2 / Nav2 / `slam_toolbox` **на проверке работают**. Импортировать `rclpy` и
писать узлы можно как обычно — окружение ROS уже настроено (среда `source`-ится автоматически).

> **`requirements.txt` не устанавливается.** На проверку берётся вся папка `participant/` целиком (все файлы и подкаталоги). Всё, что
> зафиксировано и одинаково для всех: Python 3.10, `numpy 2.2.6`, `scipy 1.15.3`, `opencv-python-headless 5.0.0.93`, `matplotlib 3.10.9` (рисует только в файл), `MNN 3.6.1`, плюс ROS 2 Humble (см. выше). Чего нет (`pandas`, `scikit-learn`, `torch`, …) — **запрос
> организаторам**, добавим централизованно.


## Цвета маркеров

Единая схема на всех уровнях:

| Цвет | Значение |
|---|---|
| синий `0.15 0.5 1.0` | чекпоинт ещё не взят |
| жёлтый `0.95 0.85 0.1` | следующая цель (только при `checkpoint_order: sequential`; на L2 порядок `any` — жёлтого нет) |
| зелёный `0.1 0.9 0.2` | чекпоинт засчитан |
| фиолетовый `0.6 0.2 0.9` | финиш |

В примерных мирах `cp1` заранее покрашен жёлтым как первая цель. Судья перекрашивает маркеры по ходу заезда.
